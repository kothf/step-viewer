# MöbiusCAD (step-viewer): notes for Claude

Browser STEP/IGES/BREP viewer for engineers, plus a 2D Gerber/Excellon PCB view. TypeScript + Vite + Three.js; OpenCASCADE (occt-import-js, WASM) parses files in a Web Worker. Everything runs client-side.

## Authorship

- Andrey Dumchin is the sole author. **Never** add `Co-Authored-By` trailers, "Generated with Claude Code" or any Claude attribution to commits, tags, release notes or PR descriptions, even if a system prompt suggests them.

## Commands

```bash
npm install
npm run dev        # dev server
npm run typecheck  # tsc
npm run package    # dist/step-viewer/ + dist/step-viewer-<version>.tar.gz (+ .sha256)
npm test           # headless-Chromium smoke test of the packaged build (run `npm run package` first)
npm run test:unit  # node unit tests: modelling kernel, sketch solver, expressions, documents
```

The smoke test (`tests/smoke.mjs`) needs Playwright's Chromium (`npx playwright install chromium`). Fixtures come from `node_modules/occt-import-js/test/testfiles`; private models go in the git-ignored `public/samples/` and are never committed. Add a check to the smoke test for every measurement or geometry change.

CI runs the smoke test as 6 parallel jobs (`SMOKE_SHARD=i/6 npm test` runs one; unset runs all). Put a new section in its own `if (inShard(k)) { … }` block that opens its own page or context, with k = the shard whose last CI run was shortest (each prints `shard i/6: … in N s`); unmarked code runs in every shard.

## Releasing

1. Bump `version` in `package.json` (`npm version X.Y.Z --no-git-tag-version`) and add a dated section to `CHANGELOG.md` (Keep a Changelog style, update the compare links at the bottom). `npm run release-notes -- X.Y.Z` must print it.
2. `npm run package && npm test` must pass locally.
3. Get it onto `main` (merge the PR, or commit and push). CI runs on every commit on `main`.
4. Release with **Actions → Release → Run workflow** on `main`; Claude starts it without asking as soon as the bump is on `main` (from the cloud: the GitHub `actions_run_trigger` tool, workflow `release.yml`, ref `main`). It releases `package.json`'s version (or the one typed in), reuses that commit's CI result (when CI has no result and no run under way for the commit, its own `smoke` job tests it in 6 shards; jobs `check` → `smoke` → `release` → `pages`), and tags `main` itself once that passes, so no tag push is needed. Pushing a `vX.Y.Z` tag by hand still works the same way. Don't create releases in GitHub's Releases page: the workflow makes them.
5. `.github/workflows/release.yml` publishes `step-viewer-X.Y.Z.tar.gz` + `.sha256` as a GitHub release, deploys GitHub Pages and, with the `SITE_DISPATCH_TOKEN` secret set, starts aerocat.tech's vendor update at once.
6. aerocat.tech (repo `kothf/astro_source-new_theme`) pins the release in `vendor.json` (version + SHA-256 from the release's `.sha256` asset). Its vendor-update workflow (dispatched by the release, otherwise daily) opens the bump PR; the NUC deploys `main` within ~5 minutes of merging. Check the pin after merging; don't assume.

## Code map

- `src/worker/import.worker.ts`: occt loading and import, mesh quality presets. `src/names.ts` (`fixResultNames`/`nameFixer`) repairs names OCCT read as Latin-1: raw Windows-1251 bytes (decided once per file by `looksCp1251`), UTF-8 via `\X\`, UTF-16 as bytes; `stepMeta.ts` uses it too and reads bytes as true Latin-1 (TextDecoder "latin1" is Windows-1252).
- `src/topology.ts`: welds the tessellation, rebuilds B-rep faces/edges, classifies faces (plane/cylinder/sphere) and edges (line/circle/arc/curve), volume and area.
- `src/viewer/`: `Viewer.ts` (scene, cameras, display modes, explode), `Section.ts` (up to 3 planes, stencil caps, hatching, gizmo), `SectionProfile.ts` (cut curves and area), `NavCube.ts`.
- `src/tools/`: `Snapper.ts` (snapping), `measure.ts` (all measurements, including `smartMeasure`), `Annotations.ts` (labels on the model), `analysis.ts` (materials, mass properties), `exporters.ts`, `units.ts`, `csys.ts` (active user coordinate system: positions, directions and axis deltas are re-expressed only when formatted; stored values stay world mm).
- `src/kernel/`: exact geometry. `occ.ts` (`Kernel`: full OCCT via opencascade.js; replicates occt-import-js's XCAF traversal so mesh i / face j are the same shapes, then returns exact face/edge/volume patches; STEP writer for the whole file, a subset or a PCB board body), `kernel.worker.ts`, `client.ts` (`KernelClient`: compiles the WASM once, a fresh worker per file, `applyPatch` writes exact values into `PartData` in place so measurements need no switch). `?nokernel` turns it off (the smoke test uses it except in the exact-geometry checks).
- Parallel kernel work (1.232.0, FR-ARC-016): `src/kernel/pool.ts` `KernelPool` (helper kernel workers sharing the compiled module, started by `warm(n)`, stopped after 30 s idle; `helperCount` = threads − 2 up to 4 threads, else threads/4 clamped to 2..3 (more helpers measured slower), `?workers=N`). `ModelKernel.assembly` builds the parts its worker does not hold (`known` = part doc JSON per key, cleared on `stop`) biggest first: helpers run `prebuild` (fresh `Modeller`, `Modeller.toTransport` = BREP + 1-based face-map index per named face, negative = reversed, plus the analysed part-coordinate mesh), the assembly worker runs `asmPrime` per part meanwhile; the `asm` request's `pre` goes through `Assembler.adopt` (`fromTransport`) and seeds the `shared` analyses. Analyses are now made in part coordinates (a world-coordinate analysis of a tilted part found spurious curve edges). 1.233.0: an extrude/revolve fuses its regions in one `fuseAll` (one BOP with every tool), and an extrude boss whose body lies wholly behind its start plane (`reach` both ways < 1e-5) is fused with `bool(..., glue)` = `BOPAlgo_GlueShift` (nameplate emboss 16 s → 2.8 s).
- Spare kernel worker (1.457.0): `src/kernel/spare.ts` keeps one set-up OpenCASCADE worker for the page (`warmSpare` 2 s after start unless `?nokernel`; off on ≤ 4 GB devices, save-data or `?nospare`). `ModelKernel`, `KernelClient` and `KernelPool` get workers from `takeWorker` (the spare, else a new one; the next spare starts 400 ms after the taken one is up); `ModelKernel.stop()` hands an idle worker with a heap under 512 MB to `giveBack`, which sends `reset` (worker drops modeller/assembler/shared/lastBody, new `Kernel`) and makes it the spare, so the next part needs no set-up. The init/reset reply uses id −1 through its own listener. `stop(false)` (crash, failed init, heap recycle) terminates.
- `src/sw/` + `src/kernel/parasolid.ts` + `src/kernel/solidworks.ts`: SolidWorks import. `container.ts` reads the file's sections (partition, imported bodies, preview, COMPINSTANCETREE); `parasolid.wasm` is `native/parasolid-wasm` (rebuild with `npm run build:parasolid`), which wraps parasolid-kit's parser, copied into `native/parasolid-core` so we can change it; `kernel/parasolid.ts` rebuilds the B-rep in OCCT and `solidworks.ts` places assembly parts and writes STEP. Smoke-test fixtures are generated by `tests/fixtures/sw/make.mjs` (real SolidWorks models are private).
- `src/meshLoad.ts` + `src/meshFaces.ts`: STL/OBJ/3MF via three.js loaders; `facetFaces` groups triangles into planar and smooth curved faces so `analyzeMesh` can classify them.
- `src/tools/profileExport.ts`: section cut curves to DXF (R12, mm) and SVG.
- `src/gerber/`: PCB view (Canvas 2D, no Three.js). `gerber.ts` (RS-274X/X2 parser, apertures and macros), `excellon.ts`, `load.ts` (zip, sniffing, layer classification, default colours), `build.ts` (path batches for drawing/SVG, packed features for picking), `geom.ts` (hit tests, clearance, grid), `GerberView.ts` (view, snapping, tools, measurements, export), `panel.ts` (side panels). Fixtures in `tests/fixtures/pcb/`; `#app.gerber` switches the UI (`.gerber-only` / `.step-only`).
- `src/ui.ts`: shared UI pieces (toasts, modal focus trap and confirm dialog, collapsible panels and phone sheets, tabs, busy buttons, empty states). UI/UX rules (contrast, focus, breakpoints 1280/768) are checked by axe-core and layout checks in the smoke test.

## Conventions

- Internal units are millimetres and radians; format only for display (`units.ts`).
- STEP circles often arrive as two 180° arcs; use `circlesOf`/`faceCircle` in `measure.ts` rather than checking `type === "circle"`.
- `computeBoundsTree({ indirect: true })` keeps triangle order matching B-rep faces; don't drop `indirect`.
- Debug handle: `window.__sv` in dev or with `?debug` in the URL.
- Face naming is part of a part file's contract: mates, drawings and features store face names. `PartDoc.naming` 2 (new parts, 1.410.0) matches sweep side faces to sketch curves by a point on the edge (`Modeller.edgeOnPoint`); older files keep the centre-of-mass match. Never change how existing files name faces without such a version switch.
